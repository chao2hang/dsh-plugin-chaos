# Agent Note：异常结束重试条

Status: implemented

[English](2026-08-23-abnormal-end-retry-strip.md) | 中文

## 问题

对话非正常结束时——回合以错误终止、回合被中断、或触发输出 token 上限——转录区展示了发生了什么，却没有给出下一步的出路。用户唯一的恢复方式是手动找出并重新输入自己的上一条消息。

## 决策

一个纯 UI 插件（`chaos-retry`）注册一个 `conversation.input.dock` 条目。它在每次渲染时从会话快照的最后一个节点推导结束状态，当会话在异常结束后处于空闲时，在输入框上方显示一条带结束状态和“重试”按钮的悬浮条。点击“重试”会把对话最后一条用户消息的文本写入输入框草稿，并通过公共 `inputActions` 提交——与输入框自身发送按钮相同的裁决、序列化和通知路径。

## 备选方案

**替换自带的 turn-error 聊天节点**（keyed 的 `conversation.chat.node` 席位）。该席位会遮蔽自带 UI：插件必须自行重绘整张失败卡片，而且入口停留在可能已滚出视口的历史里，而不是恢复动作发生的输入框旁。dock 是增量的，且始终基于当前状态。

**宿主侧重发命令或会话 RPC。** 服务端截断/重放接缝会为一个表现层需求触及核心会话语义；它还隐含对失败回合的回滚，而首版有意不做回滚。

## 后果

重试是在失败回合之上追加一条新的用户消息；不会截断残缺历史。仅支持文本是首版范围：最后一条用户消息没有可重发文本时提示条不出现，点击会用重发文本替换当前草稿。插件不拥有任何 store——所有事实都从快照推导——因此移除只需删掉组合行。
