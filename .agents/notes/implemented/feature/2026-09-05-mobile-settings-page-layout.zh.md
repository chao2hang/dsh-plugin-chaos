# Agent Note: 手机设置页收起为单行 chips 与单行外观卡片

Status: implemented

[English](2026-09-05-mobile-settings-page-layout.md) | 中文

## 问题

手机设置页把竖屏空间花在了导航上而不是内容上。分区导航是 44px 卡片的两列网格（五个分区占三行；core 自己在窄屏宽度下的横向 chips 行被 fork 的 data 属性规则覆盖掉了），外观偏好则因为桌面卡片的 180px flex 基准放不进 390px 的一行，折成了三张通栏大卡片。页面顶部，上下文状态条还在导航栏下方持续绘制，浮在设置内容上方，看上去像一条多余的横线。

## 决策

分区导航改为单行横向可滚动的 chips 行：chips 按标签文本定宽（`flex: none`），文本不会被截断，最后一个 chip 露出边缘即是滚动提示。外观行在其卡片容器上输出 `data-appearance-cubes` 锚点，移动样式表把它重排为紧凑的三列网格，全部选项一行放下。`ContextStatusBar` 观察 `[data-settings-overlay]` 的存在（与 `MobileNavBar` 用的是同一观察），专属设置页盖住对话时不渲染；store 继续发布，弹窗里的上下文明细不受影响。

## 曾考虑的替代方案

**保留两列分区网格。** 它不滚动就能看到全部入口，但把手机上最稀缺的三行竖排空间花在用户本没打算操作的导航上。

**用哈希类名选择器或 core 的媒体查询重排卡片。** module 类名按构建加哈希，且 fork 的 data 属性规则本来就压过 core 的 560px 媒体块；在 core 组件上放稳定锚点正是输入框与统计行用的同一条缝。

**用设置弹窗上的 CSS 规则隐藏状态条。** 状态条是门控到 body 的元素，弹窗的层叠管不到它；可见性应由组件自己拥有。

## 后果

设置页头部从约三行缩到标题加一行 40px chips，外观选择收进一行 68px 高的紧凑卡片。上下文状态条在整个设置页存活期间消失，关闭后恢复。外观行规格固定所输出的锚点及其三枚卡片按钮；mobile.css 规格固定 chips 行与三列重排；上下文状态条规格覆盖状态条随弹窗挂载与卸载的隐藏与恢复。
