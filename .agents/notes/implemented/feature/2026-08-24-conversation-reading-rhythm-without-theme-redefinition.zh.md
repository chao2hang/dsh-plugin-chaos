# Agent Note: 不重定义主题色的对话阅读节奏

Status: implemented

[English](2026-08-24-conversation-reading-rhythm-without-theme-redefinition.md) | 中文

## 问题

对话视图的信息本身完整，但长篇助手回答、用户提问和输入区的视觉权重过于接近。若通过更换既有蓝色主题解决，会让对话区与应用其余部分失去一致性。

## 决策

对话视图保留现有语义颜色 token，只调整几何与排版。对话记录、标题和输入区保持既有的共享宽度轴。助手正文使用紧凑的 15px/26px 阅读节奏与克制的区块间距；用户提问保留现有气泡填充与边框 token，但以更紧凑的注释式气泡呈现。sticky 输入区遮罩保证滚动时的分隔干净。

## 曾考虑的替代方案

- **将墨色与朱砂入口配色应用到对话区**：会让页面更接近受保护入口状态，但会覆盖既有应用主题，也让视觉偏好处理失去一致性。
- **为每条消息增加卡片和填充**：能在短对话中强化分组，但会让长篇助手输出变得破碎和厚重。

## 后果

- 既有浅色/深色偏好和所有颜色 token 的所有权保持不变。
- 长篇助手回答仍是主要阅读内容，但不会降低信息密度；用户消息仍易于定位，但不再成为竞争性面板。
- 既有共享宽度变量让输入卡片和记录在桌面与窄视口中保持对齐。
- CSS 改动限定在对话包内，移动端适配与 InputBar 行为可独立演进。
