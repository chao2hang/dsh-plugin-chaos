# `@deepseek-ai/dsh-plugin-chaos-retry`

[English](README.md) | 中文

对话非正常结束的一键重试：输入框上方的一条悬浮提示，点击即可重发对话最后一条用户消息。

## 行为

当对话最近一个回合非正常结束时，输入框上方会出现提示条，展示结束状态和“**重试**”按钮。以下四种结束会触发（从 Chat 目标的最后一个可见行读取）：

- 回合以错误终止（提示条同时展示失败信息）；
- 回合被中断（助手前缀被冻结）；
- 触发单次请求输出 token 上限提示；
- 崩溃恢复关闭，即回合随进程一同消亡（见下）。

## 崩溃恢复行

进程死亡的回合——服务重启、崩溃——不会写下自己的 `turn/end`；持久化层在重新加载时以 `reason.kind === 'interrupted'` 将其关闭。自带节点体系为其他每一种终止原因都提供了 Definition，唯独没有这一种，而它的「中断助手」兜底路径要求已流式产出内容作为证据。于是，在首个 token 到达前、或在工具调用与其结果之间被杀死的回合，**根本不会投影出任何东西**。

本包补上缺失的 `turn-interrupted` 节点 Definition 及其转录行，使该结束无论回合进行到哪一步都可见——也让重试条在重启后有可检测的对象。

以下情况不显示：回合仍在运行或流式输出中、队列中还有待发消息、有待处理的交互决策、失败之后对话已有新进展（新的用户消息或已完成的助手回复），以及会话已被移除。

点击“**重试**”会把最后一条用户消息的文本写入输入框草稿并通过公共输入动作提交——与输入框发送按钮相同的路径，命令裁决、序列化和通知仍由输入状态机负责。重发是在同一会话中追加一条新的用户消息，不会截断失败的回合。

## 组合

web-app 补丁层以 `chaos-retry` 挂载本包。客户端半区贡献 `turn-interrupted` 节点 Definition 及其 keyed `conversation.chat.node` 渲染器，外加一个 `conversation.input.dock` 条目。它不拥有任何 store：异常结束状态在每次渲染时从会话快照推导，文案位于 `chaos-retry` 语言命名空间。移除本插件即移除提示条和崩溃恢复行；对话本身与恢复机制均不受影响。

它与 `chaos-restart` 配合：后者的「系统」设置区块执行重启，而本插件负责在重启后提供恢复入口。

## 模型体验

无。插件通过常规输入框路径重发最后一条用户消息；重发文本作为普通用户文本到达模型，插件不贡献固定提示区块。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- 重试只重发文本。最后一条用户消息包含图片（或没有文本）时提示条不出现，因为这里的草稿写入路径只支持文本。
- 点击“**重试**”会用重发文本替换当前输入框草稿中的内容。
- 重发不会回滚失败回合的残缺历史，而是在其上追加新回合。

**运行时不变式：** 不发布伴生入口。唯一的 conversation.input.dock 注册的处置由 HMR 安全 spec 证明；插件不持有任何存储——异常结束状态每次渲染从会话快照派生，不发出 cordis 事件，也不持有跨插件可变状态。
