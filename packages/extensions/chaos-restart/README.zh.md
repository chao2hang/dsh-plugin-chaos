# `@deepseek-ai/dsh-plugin-chaos-restart`

[English](README.md) | 中文

服务自重启：一对替换当前进程的宿主路由，以及设置页中驱动它的「系统」区块。

## 行为

宿主半区在 web 服务器上注册两个路由：

- `GET /api/system/status` 报告 `canRestart`，取自可选的 `processControl` 服务。无法派生后继进程的启动方式会报告 `false`。
- `POST /api/system/restart` 会等待 `processControl` 确认后继进程存活过启动窗口。替换无法开始时会以 HTTP 503 返回 `{ ok: false, reason }`；返回 `{ ok: true }` 后，`processControl` 在下一个事件循环轮次停止当前进程，以便响应送达浏览器。

浏览器半区在设置页添加「**系统**」区块。当宿主报告不支持重启时完全隐藏该控件；重启需经过确认步骤；确认框在当前有会话正在运行时给出警告。宿主接受后，区块进入等待状态——重连由连接层负责，页面会自行恢复。

## 重启会失去什么，不会失去什么

会话是持久的：它们保存在磁盘的会话日志里而非进程内存中，因此重启不会丢失对话历史。重启真正终止的是**进行中的回合**，它随进程一同消亡。

这样的回合不会写下自己的 `turn/end`。持久化层在重新加载时以 `reason.kind === 'interrupted'` 将其关闭来修复，退出前记录的所有事件均完整保留。`chaos-retry` 插件会渲染这一关闭标记并提供一键重发；没有它，恢复依然正确，只是转录区没有对应的行。

重启被设计为需确认的运维动作而非自动恢复。被中断的回合可能已经执行过带副作用的工具——写文件、跑命令——而日志无法可靠区分「工具已完成但结果未记录」和「工具从未运行」，因此是否重放由操作者决定。

## 组合

`chaos-bundle/cordis.patch.yml` 与 web-app 补丁层以 `chaos-restart` 挂载本包，其 `enabled` 配置默认为 true。宿主半区需要 `processControl`（`@deepseek-ai/dsh-process-control`）——缺少它时路由仍会应答并报告不支持。移除该行会同时移除路由和设置区块。本包 tsconfig 恢复客户端基座刻意去除的 ambient `node` 类型，因为宿主半区提供 HTTP 路由。

## 模型体验

无。本包在浏览器中渲染设置区块和宿主重启路由；这里没有任何内容进入模型请求。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- 区块报告的是已接受，而非完成：它无法观测独立的后继启动失败。启动器会先释放当前应用树及其 listener，再派生后继进程，因此固定端口不会造成此类失败。
- `canRestart` 是启动方式的能力，不是权限。该端点的保护来自启用远程访问时 auth 插件的请求守卫；在回环地址上它与其他本地路由一样可达。
- 确认框中的计数只覆盖当前浏览器已知的会话，不含其他已连接客户端正在运行的回合。

**运行时不变式：** 不发布伴生入口。宿主路由无状态地直通 processControl 服务，设置区块的状态每次渲染从该服务派生；注册处置由 HMR 安全 spec 证明。
